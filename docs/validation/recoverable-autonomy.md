# 实测问题修复验收

基于用户提供的 wordcount 试跑报告，本轮修复框架能力缺口；未直接修改另一台机器的原 run 或清理其工作树。

- 规划错误本身属于生成内容质量；框架增加命令环境预检和错误规划重试，明确区分未来文件与已通过测试。
- 执行中修订缺失属于框架问题：新增受控 run.revise，保留已接受工作，修订后重新走验证与审查。
- 空 writes 实际表示未知范围；本轮阻断没有候选改动的无效失败重试，保留正常未知写集实现行为。
- 粒度问题增加完整交付单元指导和多 source_ids 覆盖；不声称静态框架能保证任意模型产生最少任务。
- 清理覆盖更多终态工作目录并明确保留原因，可选安全删除已合入分支。
- 批量认领减少每一轮的独立 claim 往返；仍由宿主安排每个新上下文。

已完成针对性实测：本机 Node 24.21.0 的裸测试目录命令出现 MODULE_NOT_FOUND，明确测试文件及默认发现通过；核心回归覆盖已验证任务保留、晚期命令修订、旧修复失效和幂等/CAS；真实进程 E2E 先集成 add，随后 multiply 验证命令失败，修正后同 run 完成范围，首任务未重做且失败证据保留。

本轮真实语义进程使用独立 mock host/worker 检验框架状态机。未重跑用户相同模型、相同提示的 38 分钟实验，因此不报告真实 LLM 耗时或任务数量的改善百分比。

最终全量门禁：162 项 Rust 测试（含真实 OpenSpec 合约）、56 项 JS/发布测试、82 项 E2E、10 项 strict specs 全通过。最后追加的原生覆盖刷新用例及账本/环境复核共 52 项专项 Rust 检查通过，最终 Clippy 无警告。新增 schema 3 保护在首次修订同事务生效；无关 roadmap 更新保留覆盖，原生检查明确变更时记录覆盖退役。
